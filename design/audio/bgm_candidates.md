# 배경음 후보 목록과 확정 결과

- 상태: **확정·제작 완료(2단계).** 결과는 맨 아래 「확정 결과(2단계)」. 아래 1단계 표는 후보를 고를 때의 기록으로 남겨 둔다.
- 승인 기록: **2026-10-01, 선생님이 대화창에서 직접 승인.** 1순위 목록을 그대로(제목 화면 「청성곡」 유지), 다운로드 양식 값(사용목적 비상업용 / 용도 교육용 / 기관명 온양여자고등학교)도 승인. s1은 「처용가」 악구 정보에 가객 이름이 있으면 대안 「수제천」으로 바꾸는 조건도 승인 → 바꿨다(아래).
- 내려받기: 메인 세션이 선생님 승인 뒤 `tools/gugak_fetch.py`로 승인된 악구 75개만 받았다(`design/audio/approved_ids.json`, 원본 212MB는 `assets/raw/audio/`, 커밋하지 않음).
- 출처: 국립국악원 「국악기 디지털 음원」(디지털 이음) **악구 다운로드** — https://www.gugak.go.kr/digitaleum/front/phrase/list.do
- 이용 조건: **공공누리 제1유형(출처표시)**. 사이트 문구는 "국립국악원이 창작한 이 저작물은 공공누리 출처표시 조건에 따라 이용 할 수 있습니다."
- 조사 방법(2026-10-01): 사이트가 목록 화면에 쓰는 **목록 조회 API**(`getInstrumentList.do` → `getGenreList.do` → `getFileList.do`, 악구 정보 `getFileInfo.do`)로 악기 23종, 악구 13,563개의 이름·장단·위치·BPM·지역만 읽었다. 음원 파일과 미리듣기는 받지 않았다. 미리듣기 주소는 사이트 세션 없이 열면 401이 난다.
- 시리즈 선례: 영웅의 길(`영웅소설/design/bgm_plan.md`, 13곡 8.6MB)과 도산십이곡(`도산십이곡/tools/gugak_fetch.py`, 7곡 4.3MB)이 같은 사이트, 같은 방식을 썼다. 길이·용량 중 **확인**이라고 적은 것은 도산십이곡이 받아 둔 같은 악구 원본을 ffprobe로 잰 값이다.

## 고른 기준

1. **한 악기 독주 악구만** 쓴다. 성악(남창·여창)은 넣지 않았다. 읽을 글이 많은 장면이라 노랫말이 겹치면 안 된다.
2. 같은 연주의 **번호가 이어지는 악구**를 고른다. 순서대로 이으면 실제 곡의 한 대목이 되고, 되풀이 이음매도 잡기 쉽다.
3. 조용하고 오래 들어도 거슬리지 않는 곡을 먼저 고른다. 반 전체가 동시에 켜도 시끄럽지 않도록 타악기(장구·꽹과리·징)는 뺐다.
4. 시대와 맞는 곡이 있으면 그 곡을 쓴다. 「여민락」은 세종 때 용비어천가에 붙인 곡이고, 「처용가」는 사이트 정보에 지역이 '신라'로 적혀 있다. 「봉래의」는 세종 때 만든 용비어천가 정재 음악이다. 15세기 민간 음악은 녹음으로 남은 것이 없으므로, 장터 장면에는 뒷시대 경기 민간풍류를 '분위기용'으로 쓴다.

## 장면별 후보

- 주소 칸: 악구마다 따로 열리는 고유 페이지가 **없다**. 모두 `악구 다운로드` 목록(위 주소)에서 **악기 → 갈래 → 악곡**을 눌러 찾고, 악구 이름을 누르면 정보 창(미리듣기·다운로드 단추)이 뜬다. 표에는 그 경로를 적었다.
- 형식: 사이트가 내려 주는 원본은 **WAV**다. 도산십이곡에서 잰 값으로 관악(w1·w3 계열)은 모노 44.1kHz 약 132KB/초, 현악(S2·S5 계열)은 스테레오 44.1kHz 약 265KB/초였다. 처음 쓰는 계열(w6·s1·S3·W7)은 같은 비율로 **추정**했다.
- 길이: 목록 API에 길이가 없는 악구는 BPM·장단으로 **추정**했다(2단계에서 ffprobe로 다시 잰다).

## 내려받기 계획

**선생님 확인 전에는 아무것도 하지 않는다.**

### 1. 받기 (2단계, 선생님 확인 뒤)

- 로그인은 필요 없다. 다운로드 단추를 누르면 **사용목적·용도·기관명(소속)**을 적는 창이 뜬다. 이 창에 값을 넣어 보내는 일은 선생님 확인을 받은 값으로만 한다.
  - 선례(영웅의 길·도산십이곡): 사용목적 **비상업용**, 용도 **교육용**, 기관명 **온양여자고등학교**.
- 도구: 도산십이곡의 `tools/gugak_fetch.py`를 이 저장소 `tools/`로 옮겨 쓰거나, `/aside-browser`로 사이트에서 직접 받는다. 30개씩 3번.
- 원본 위치: `assets/raw/bgm/` (커밋하지 않음). 받은 악구 목록은 `assets/raw/bgm/picks.json`에 남긴다.

### 2. 재기

`ffprobe`(C:\Users\wnsdl\ffmpeg\bin)로 악구마다 길이·채널·표본율을, `ebur128`로 소리 크기(LUFS)·최고점을, `silencedetect`로 앞뒤 무음을 잰다. 표에 **추정**이라고 적은 길이·용량은 이 값으로 고친다(도산십이곡 `bgm_probe.py` 방식).

```sh
ffprobe -v error -show_entries format=duration:stream=channels,sample_rate -of json in.wav
ffmpeg -hide_banner -i in.wav -af ebur128=peak=true -f null -
ffmpeg -hide_banner -i in.wav -af silencedetect=n=-48dB:d=0.3 -f null -
```

### 3. 다듬기

1. **모노로 합치기**: 스테레오 원본(현악)은 `-ac 1`로 줄인다. 휴대폰·태블릿 스피커는 거의 모노라 잃는 것이 없다.
2. **앞뒤 무음 정리**: −48dB 아래 무음을 앞 0.10초, 뒤 0.35초만 남기고 자른다.
3. **잇기**: 번호가 이어지는 악구는 5~40ms 등전력 크로스페이드로 바로 붙인다. 띄엄띄엄인 악구(거문고 「타령」 등)는 **장단 경계에서** 이어 박이 밀리지 않게 한다.
   ```sh
   ffmpeg -i a.wav -i b.wav -filter_complex "[0][1]acrossfade=d=0.04:c1=qsin:c2=qsin" ab.wav
   ```
4. **되풀이 이음매**: 끝 1.5~3초를 곡 처음과 겹쳐(무장단 곡은 2.5~3초) 되풀이할 때 툭 끊기지 않게 한다. 곡 길이는 60~120초로 맞춘다.
5. **음량 맞추기**: ffmpeg `loudnorm` 2패스로 모든 곡을 **−18 LUFS**, True Peak **−1.5 dBTP**에 맞춘다(시리즈 범위 −17~−20의 가운데). 피리·대피리처럼 날카로운 곡은 −19~−20 LUFS로 한 단계 낮춘다. 여러 기기가 한 교실에서 함께 울리므로 게임 안 기본 음량도 낮게(0.4~0.5) 둔다.
   ```sh
   # 1패스: 측정값(JSON) 얻기
   ffmpeg -i joined.wav -af loudnorm=I=-18:TP=-1.5:LRA=11:print_format=json -f null -
   # 2패스: 측정값을 넣어 선형 보정
   ffmpeg -i joined.wav -af loudnorm=I=-18:TP=-1.5:LRA=11:measured_I=..:measured_TP=..:measured_LRA=..:measured_thresh=..:offset=..:linear=true -ar 44100 -ac 1 norm.wav
   ```
6. **줄이기**: mp3 모노 **64kbps**(소리가 거친 곡만 80~96kbps), 44.1kHz.
   ```sh
   ffmpeg -i norm.wav -ac 1 -ar 44100 -c:a libmp3lame -b:a 64k -map_metadata -1 assets/bgm/bgm_s4.mp3
   ```
7. **점검**: 이음새 20ms 앞뒤 소리 크기 차, 한 샘플 튐, 곡 사이 음량 차(±1LU), 클리핑을 잰다(소리 해전 `check-audio`, 도산십이곡 `tests/bgm.mjs` 방식).
8. **기록**: 곡마다 쓴 악구 ID·악곡·위치·길이·LUFS를 `assets/bgm/bgm.json`과 `assets/audio/CREDITS.txt`에 남긴다.

## 확정 결과(2단계, 2026-10-01)

### 1단계 안에서 바뀐 것

- **s1**: 「처용가」(W7 계열) 악구 정보에 가객 이름(홍창남)이 적혀 있어, 승인된 조건대로 **대금 연례악 「수제천」**으로 바꿨다. s7이 피리 「수제천」(`w1-440`)이므로 s1은 다른 악기·다른 녹음인 대금 `w3-440-010, 022, 032, 042`를 썼다. 그래서 받은 악구는 83개가 아니라 **75개**다.
- **이음매 편집**: 계획의 "loudnorm 2패스" 대신 **이득 + 봉우리 리미터(천장 −2.5 dBFS)**로 맞추고, 결과 MP3를 다시 재서 ±0.3 LU 안에 들 때까지 고쳤다. 양금·거문고·가야금처럼 뜯거나 치는 악기는 봉우리가 높아 loudnorm 선형 모드로는 −18 LUFS까지 올리지 못했다(−19.6~−19.9에서 멈춤).
- **짧은 곡 늘리기**: s0 「갈잎소리」는 악구 4개를 합쳐도 12초라서, 악구 묶음을 4번 되풀이해 47초로 늘렸다. s3도 39초라 2번 되풀이했다(40초 미만이면 되풀이).
- **파일 이름**: s0 악구 파일은 악구 번호가 아니라 원래 mp3 이름(`16_갈잎소리1_1.wav` 등)으로 왔다. `tools/bgm_build.py`의 `ALIAS`가 번호와 짝지어 준다.

### 만든 방법 (`tools/bgm_build.py`)

1. 악구를 모노 44.1kHz로 읽는다(현악 원본은 스테레오 24비트, 「갈잎소리」는 96kHz 32비트).
2. 무장단 곡(제목·s1·s7)만 −48dB 아래 앞뒤 무음을 정리한다(앞 0.10초·뒤 0.35초 남김). 장단이 있는 곡은 악구 길이가 장단에 딱 맞아(예: 거문고 「타령」 8.000초) 자르지 않는다.
3. 번호 순서대로 등전력 크로스페이드로 잇는다(무장단 40ms, 나머지 15ms).
4. 되풀이 이음매: 끝 일부를 처음과 겹쳐 앞에 둔다(무장단 2.5초, 나머지 0.6초). 그리고 파일 양끝에 30ms 페이드를 준다. MP3 인코더 여백 때문에 되풀이할 때 아주 짧은 틈이 생겨도 '딱' 소리가 나지 않게 하려는 것이다.
5. 이득 + `alimiter`(천장 −2.5 dBFS)로 −18 LUFS에 맞춘다. 결과 MP3를 `ebur128`로 다시 재서 ±0.3 LU 밖이면 고쳐 다시 만든다.
6. `libmp3lame` 모노 44.1kHz **64kbps**, 메타데이터 없음. 측정값은 `assets/raw/audio/_build.json`에 남긴다(커밋하지 않음).

### 측정값(결과 MP3를 ffmpeg `ebur128=peak=true`로 잼)
